# Verified Scientific Model Marketplace

## Idea
Commercial layer on top of the Verified Model Registry: researchers, consultants and engineering companies can publish licensed model packages with evidence, and customers can buy/use them through a standard API.

A listing is not merely source code. It includes:
- executable model
- semantic interface
- validation passport
- supported parameter/validity range
- tests and benchmark results
- license terms
- provenance/citations
- optional support/SLA

## Material value
Creates a direct monetization channel for specialists who currently sell consulting hours or proprietary spreadsheets/scripts. Buyers avoid rebuilding and validating standard models internally.

## Strategic value
If the registry format becomes useful, marketplace liquidity creates a network effect: more trusted models attract users; more users attract model publishers.

## Business models
- transaction fee
- private enterprise marketplace
- paid certified/validated packages
- support/SLA revenue
- usage-based execution API
- publisher/vendor storefronts

## Risk
Marketplace should come **after** the technical package format and verification tooling are useful. Starting with marketplace before trusted supply/demand exists would be premature.

## MVP
No broad marketplace initially. Publish a first-party catalog of 20-50 validated model packages and allow a few invited third-party packages with manual review.
